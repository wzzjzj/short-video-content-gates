# 五道内容闸门

参考视频分析的输入、证据等级和迁移边界见 `reference-analysis.md`。参考视频的播放、互动、热门标签、作者权威或完成度不构成本项目的公共需求证明，也不能抵消本项目在任何一道闸门中的缺口。

## 抖音 1080×1920 通用 UI 安全区

这是抖音竖屏视频唯一的共享坐标基线，同时适用于个人号、门店号以及挂或不挂团购的作品。界面组件可以不同，规避区域不能因此缩小。机器可读坐标只保存在 `douyin-1080x1920-safe-zones.json`；本门禁的日常证据工具与严格发布检查共同读取该文件，项目不得复制或覆盖。

该基线定义顶部平台区、右侧操作区、左下及底部信息区、核心内容区、居中 3:4 封面裁切区，以及主页 360×480 缩略图的左上和左下叠加区。坐标原点在画布左上角，单位为像素；执行抖音 1080×1920 检查前必须读取该 JSON。

“关键元素”包括标题、正文、字幕、Logo、CTA、标签，以及任何可能被识别为文案或必须读清的装饰文字。背景纹理和不承载信息的图形可以越出核心安全区，但不能让关键元素变得难读。

### 首版布局

HyperFrames 在第一版 HTML 排版前运行 `node <本 Skill>/scripts/safe-layout.mjs`，把输出的 CSS 纳入现有样式，并在每个场景内用 `.platform-safe-content` 包住标题、字幕、品牌、CTA 和可读标签。数值由上述唯一 JSON 生成，不维护另一份坐标表。其他工具使用同一坐标源设置对应的信息层区域。

该容器坐标相对于完整的 1080×1920 场景；照片、纹理放在容器外铺满画布。容器内优先使用正常流、flex 或 grid；局部定位以容器为参照，不沿用全画布的 top/left。不要通过 overflow:hidden 隐藏越界文字来冒充安全：文本完整边界及其可读期间的动画轨迹都需留在区域内，缩放和位移作用于背景或独立内层时也要核对实际效果。封面仍按原有裁切证据核对，不直接把播放页容器当作封面裁切通过证明。

### 实际画面验收

在第一次提交完整预览前，结合连续预览核对各场景实际可读时段的关键内容；HTML配置绑定须对应观众看到的文字，隐藏副本或源码匹配不能证明内容已展示。项目检查器负责型号、价格等事实核对，本节负责实际呈现。

抖音1080×1920的同一次预览验收按以下顺序执行，不再额外强制静态预检：
1. HyperFrames 单时间线 HTML 用 `node scripts/check-preview-layout.mjs --html <实际页面> --times <各布局代表秒数及已知运动极值，逗号分隔> --out-dir <空的QA目录>` 代替单独抽取预览代表帧。工具按实际时间线每0.25秒及指定时间检查可见文字边界，生成代表帧和 `layout-report.json`；没有接入信息层、越界或裁切返回BLOCK。初始隐藏不代表实际不可见；官方 `data-layout-allow-caption-zone` 不豁免抖音安全边界。采样不能证明采样间、Canvas/SVG/伪元素文字或遮挡安全，仍需连续观看及人工核对。多时间线/其他引擎不强行套用，按同一基线检查真实渲染证据，记录该工具不适用。
2. 读取项目指定发布模板，按模板在指定发布资料文件内填齐本次内容（包括首评等项目字段）；脚本中的草稿不替代该文件。运行 `python scripts/make-safe-area-evidence.py --frame <实际代表帧> [--frame <更多帧>] --cover <实际交付封面> --publish <发布资料文件> --template <项目模板> --out-dir <空的证据目录>`；上述HTML同时传 `--layout-report <layout-report.json>`。它核对资料缺项并继承布局失败，不生成质量PASS。
3. 查看播放页遮罩、3:4封面和主页缩略图，逐一核对顶部、右侧、左下/底部关键内容及已知运动极值；关键内容落在遮罩内即BLOCK，即使技术检查通过或用户确认也不能改为PASS。封面直接传实际交付文件：9:16自动居中裁切，原生3:4直接生成缩略图；如果另有9:16源图，传 `--cover-source <源图>` 核对交付裁切一致性，不另写裁切坐标。
4. 在既有BRIEF记录已查看的画面/封面、区域结论和问题修订。机器结果为BLOCK/INCOMPLETE时不得写PASS；机器无发现也不能代替目视与连续观看。修改关键布局、文字、封面或发布资料后只重查受影响项，旧证据保留且不沿用旧结论。布局报告绑定已加载的本地依赖与截图指纹；依赖改变、截图不匹配或旧报告缺少溯源时，重查受影响画面。`evidence.json`是工具输入/输出溯源，不是第二份门禁结论；严格发布审计仍按需。

其他平台或画幅依据对应实际界面证据验收，不缩放套用抖音坐标。项目不得保存另一套safeZones；共享检查器发现自定义坐标时仍须BLOCK。

该基线采用 2026-08-26 对抖音实机播放页和主页截图归一化测量后确认的统一口径，并在 2026-08-30 经多个项目的实际遮挡案例复核。客户端界面改变时先记录新证据；只有用户明确批准，才更新这一个共享基线，不在项目内另建坐标规则。

### 按需 HTML 诊断

排查隐藏配置绑定或静态文字越界时，可运行 `node <本 Skill>/scripts/check-visible-layout.mjs --html <页面>`；抖音1080×1920加 `--platform douyin`。它不是每条视频的必经检查。工具禁用页面脚本与网络，不能验证动画和动态内容；初始隐藏可能误报，结果须结合实际渲染判断。`NO_STATIC_FINDINGS` 不代表质量PASS；启动失败或内容未加载表示未验证。

## 发布硬停止与职责边界

本 Skill 只回答当前内容或待发布材料是 `PASS`、`REVISE`、`BLOCK` 还是有效 `EXCEPTION`，不维护 `WORKING`、`PREVIEW_READY`、`FINALIZING`、`COMPLETE` 等制作状态，也不设置用户确认点。intake、script-review 和 pre-production 的 BLOCK 是内容风险结论，不是对本地草稿、预览、测试件或制作交付的授权判定。

`pre-publish` 是按需严格审计，不是日常制作阶段。只有用户明确要求判断“能否发布”或要求智能体执行外部发布时，才绑定待发布成片与封面的哈希及叠层、裁切证据；此时只有 PASS 才能标记“可发布”或由智能体执行外部发布。普通本地制作不创建 `release_gate`、不等待该审计，也不因此延迟交付或重新打开已完成任务。已经发布不能倒推 PASS。

## 内容实质总检查

五道闸门不只检查“有没有主题”和“包装是否完整”，还要检查承诺是否被真实内容兑现。工具名、流程名、术语、问题复述、氛围画面和口号本身不算内容实质；它们只有承载明确答案、论点、证据、方法、结果或目标体验时才有价值。

先确定内容类型，再检查对应交付：

- 解决问题或教程：给出明确答案、判断条件或可执行方法，并说明预期结果；观众应知道在什么情况下做什么、如何判断是否有效。只说“要检查”“要注意”或列出工具及其职责，不算解决方案。
- 解释或评论：给出清晰论点及足以支撑它的事实、案例、演示或推理链；只罗列现象而不作判断，不算论点兑现。
- 叙事、情绪或展示：不强制操作步骤，但必须有可识别的目标体验、推进和回报，不能用知识教程的承诺包装纯氛围内容。
- 商业转化：除上述适用要求外，具体利益、产品能力和行动理由必须可核验，并符合项目的商业事实边界。

内容实质至少回答以下问题；不适用项应说明原因，不能留空：

1. **核心结论或目标回报**：观众看完实际得到什么答案、判断、理解、方法、结果或体验？
2. **承诺范围一致性**：标题、封面、开头、公共需求和正文方法是否解决同一范围的问题？在 BRIEF 内缩小承诺，不能抵消面向观众的宽泛标题或开头。
3. **支撑依据**：哪些事实、来源、案例、演示、个人经验标注或推理支撑它？证据强度应与主张风险匹配。
4. **观众可用性**：解决问题类是否给出可执行动作、判断条件、顺序或预期结果；其他类型是否给出可复述的信息增量或明确体验回报？
5. **适用边界**：哪些条件、限制、例外或事实/观点边界会影响结论？仅在确有边界时展开，不能为了形式虚构限制。
6. **场景兑现**：每个核心场景主要承载哪项结论、证据、动作、结果或体验推进？将实际所用图像与同段旁白、字幕主张对应；文件名和配置文字校验不能证明图中对象身份，未核实素材不能以“氛围”名义暗示其就是所讲对象。复用相同照片须有内容依据，不靠改名复制规避重复媒体提示。只承担重复包装的场景应删除或压缩。

判定：

- 承诺解决问题，却没有明确答案、判断规则或可执行方法：BLOCK。
- 标题、封面或开头承诺普遍解决一个问题，正文却只介绍某个特定工作流，且没有在承诺处明确适用条件：BLOCK。
- 承诺解释或评论，却无法写出明确论点，或正文只有现象和口号：BLOCK。
- 事实性主张缺少与风险相称的证据，高风险、商业或来源性事实无法核实：BLOCK；一般主张证据不足但可补：REVISE。
- 已有核心结论，但方法只有工具名和职责，或判断条件、动作、预期结果、推理、边界、场景兑现仍含糊：REVISE；若因此无法兑现已明确承诺的解决结果：BLOCK。
- 包装、工具和术语占据主要时长，实质信息不足以兑现承诺：REVISE；若前 5 秒明确承诺解决而全文没有解决方案：BLOCK。

## 1. 公共需求

回答：谁为什么现在愿意停下来？

可接受证据包括搜索需求、评论问题、现实痛点、热点与账号受众重叠、历史内容反馈、明确实验假设。只有“我想讲”“工具更新了”“已有素材”不构成公共需求。

- 没有目标观众、需求或观看理由：BLOCK。
- 实验、艺术表达或个人记录可用 EXCEPTION，但必须写明非标准目标和批准范围。

## 2. 前 2 秒进入理由

第一帧至约 2 秒内应出现清晰的停留理由，例如问题、结果、反差、故障、证据、熟悉对象或正在发生的动作。工具名和背景介绍只有在本身直接构成观众价值时才算进入理由。

- 找不到可定位的进入理由：REVISE。
- 已知开头主要是工具介绍、背景铺垫或无信息氛围，且没有观众价值：BLOCK，并给出最小修订方向。
- 特殊形式故意延迟揭示时，只能以 EXCEPTION 放行并记录理由。

## 3. 前 5 秒收益或承诺

约 5 秒内，观众应知道继续看能得到什么结果、答案、理解或情绪回报。模糊悬念不能替代承诺；不足 5 秒的视频应立即兑现。

- 前 5 秒主要介绍工具或背景，仍没有观众收益：BLOCK。
- 前 5 秒承诺“解决、教会、看懂”，正文必须提供与承诺对应的答案、方法或论证；不能把承诺本身当作兑现。
- 有方向但承诺含糊：REVISE。
- 2 秒和 5 秒是结构检查点，不是对留存率的保证。

## 4. 正文持续兑现单一命题

整条视频只维护一个核心承诺，时长由兑现需要决定；正文持续提供信息、证据、推理、可执行方法、转折、示范、结果或目标体验。制作流程只有在它本身就是观众需要的答案时才算正文价值。

- 无法写出唯一核心承诺：BLOCK。
- 解决问题类没有答案、判断规则或可执行方法，或对外承诺范围明显大于正文方法适用范围；解释评论类没有论点；叙事展示类没有目标回报：BLOCK。
- 同时承诺多个核心问题、内容漂移、时长明显超过承载需要、包装重复而信息不足：REVISE。
- 核心场景无法对应任何结论、证据、方法、结果或体验推进：REVISE。
- 不规定跨账号统一时长或完播阈值。

## 5. 流量或行为接力

明确看完后为什么会搜索、评论、收藏、分享，或执行当前项目定义的下一步动作。接力可以由内容价值和发布入口自然承接，不要求在画面、旁白或文案中加入行动口号。

商业项目的目标人群匹配和转化可信度必须反向作用于前四道闸门，不作为简单附加的“第六关”。

- 没有任何后续行为设计：REVISE。
- 涉及价格、设备、配置、优惠、活动、地址、营业时间等可核验事实，却未按当前项目权威事实源验证：BLOCK。
- 本 Skill 不保存门店路径、事实值或核验细节。

## 判定分级

### BLOCK

- 没有公共需求说明。
- 没有唯一核心承诺。
- 已知前 5 秒仍主要介绍工具或背景，且没有观众收益。
- 承诺解决问题却没有答案、判断规则或可执行方法，或承诺解释却没有明确论点。
- 规定的内容表现验收未完成。
- 抖音关键文字、字幕、Logo 或 CTA 超出通用核心安全区，或最终成片、封面缺少平台 UI 与裁切复核证据。
- 商业或来源性事实未经项目权威源核实。

### REVISE

- 前 2 秒进入理由不清楚。
- 同时承诺多个核心问题。
- 时长与信息量明显不匹配。
- 已有结论但证据、推理、操作条件、适用边界或场景兑现不足。
- 缺少搜索、评论、收藏、分享或项目定义的下一步行为。
- 商业内容的目标人群、内容放大和转化路径明显不匹配。

### 观察项

预测跳出、预测完播、热点强度、互动预测及所有具体数值阈值都属于观察项。只能与当前账号、平台、时长和统计口径一致的基线比较，不能伪装成硬规则。

## 例外边界

EXCEPTION 只适用于有意的形式实验或目标偏离，必须记录批准者、理由、范围和日期。不得用例外绕过平台 UI 安全区、商业事实核验、虚假画面、隐私、安全、版权、平台规则或项目数据边界。
